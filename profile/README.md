<p>Claude稳定访问住宅IP服务器，稳定性的关键在于你怎么看待它：它是业务的一部分，还是一个可以随便重启的配件。当成业务的一部分，就会考虑单点、冗余和扩容；当成配件，出问题时才发现没有准备。</p>

<p>第一个取舍是单点。一台转发服务器就是一条命，它挂了所有请求都断。要么做双机热备，要么准备一套能在几分钟内顶上的替代配置。前者的成本是双倍的机器，后者的成本是一次演练和一份文档，两条路都比没有准备好。</p>

<p>第二个取舍是冗余的层次。机器冗余、线路冗余、上游冗余，三层是不同的东西。只做机器冗余，线路断了照样全停；只做线路冗余，机器挂了照样全停。要按自己的风险点来选，不要盲目堆。</p>

<p>第三个取舍是扩容节奏。住宅IP服务器通常不是性能瓶颈，瓶颈在出口带宽和连接数。扩容前先确认瓶颈在哪，否则加了机器速度也没变，只是多花了钱。</p>

<p>三个取舍之外，还有一个常被忽略的稳定因素：配置的可回滚。改错一次配置，可能要停机半小时排查。改之前导出、改完观察、出问题能退回，这套动作花不了几分钟，却能省下大量停机时间。</p>

<p>还有一点关于期望：自建服务器能提升的是可控性，不是可靠性。可靠性来自冗余和演练，而这两件事都需要投入，不会因为机器是自己的就自动拥有。</p>

<p>最后，把服务器的运行状态纳入监控。CPU、内存、连接数、出口质量，四项里有任何一项异常，都应该能提前发现，而不是等业务方来反馈。</p>
